# HemaCare — Phase 13 Production Security Audit

**Audit Date:** August 2026  
**System Under Review:** HemaCare Blood Donation Management Platform  
**Target Architecture:** Modular Monolith (React 19, TypeScript, Express, PostgreSQL, Prisma)

---

## Executive Summary
This document provides a systematic security audit covering 26 security domains across authentication, authorization, session management, data privacy, concurrency, and operational resilience. Each domain is classified by risk severity, detailing existing behaviors, identified gaps, and applied remediation.

---

## Security Domains & Findings Matrix

| # | Security Domain | Severity | Current Baseline | Risk | Remediation / Hardening | Test Coverage | Status |
|---|---|---|---|---|---|---|---|
| **1** | **Authentication & Password Hashing** | HIGH | bcrypt 12 rounds, HttpOnly cookie tokens. | Weak passwords or brute-force attempts. | Minimum 8-char complexity with uppercase, lowercase, numbers, and symbols. Rate-limited auth endpoints. | `auth.test.ts`, `hardening-security.test.ts` | **RESOLVED** |
| **2** | **Session Invalidation** | HIGH | JWT stored in HttpOnly cookie; logout clears cookie, but token remained stateless until expiry. | Compromised token remains valid until 7-day expiration even after password change. | Introduced `sessionVersion` counter in `User` model and JWT payload. Any password reset/change increments version, revoking previous tokens. | `session-revocation.test.ts` | **RESOLVED** |
| **3** | **Password Reset & Recovery** | HIGH | No self-service reset existed. | Account lockout or insecure out-of-band password resets. | Implemented cryptographic token generator, storing SHA-256 hashes in `PasswordResetToken` table with 1-hour single-use expiry. Generic email responses prevent user enumeration. | `session-revocation.test.ts` | **RESOLVED** |
| **4** | **CSRF Protection** | HIGH | Relies solely on `SameSite=Lax` cookies. | Cross-site POST/PUT requests from subdomains or older browsers could forge state-changing mutations. | Implemented strict Origin/Referer verification middleware (`csrf.middleware.ts`) for state-changing HTTP methods (`POST`, `PUT`, `PATCH`, `DELETE`). | `csrf-security.test.ts` | **RESOLVED** |
| **5** | **Authorization & RBAC** | CRITICAL | Strict `DONOR` vs `ADMIN` role middleware with session-derived identities. | Privilege escalation if client-supplied role or ID were trusted. | Role strictly enforced on all admin routes. Registration payload role overrides ignored. | `authorization-security.test.ts` | **RESOLVED** |
| **6** | **Insecure Direct Object References (IDOR)** | CRITICAL | Donor endpoints query by `donorId` resolved from verified JWT session. | Donor A reading or accepting Donor B's blood donation opportunities. | Explicit ownership checks rejecting mismatched donor IDs (`403 Forbidden` / `404 Not Found`). | `opportunity.test.ts`, `notification.test.ts` | **RESOLVED** |
| **7** | **Patient Privacy & Information Disclosure** | CRITICAL | Raw database models previously held patient reference & notes. | Exposing confidential patient diagnostics or hospital records to donor applicants. | Strict DTO projection stripping patient references, diagnosis, and coordinator notes from donor-facing responses. | `opportunity.test.ts` | **RESOLVED** |
| **8** | **Concurrency & Double-Fulfillment** | HIGH | Single update query on donation fulfillment. | Concurrent donation entries could over-fulfill requests or accept duplicate opportunities. | Atomic `prisma.$transaction` with status precondition checks and anti-fatigue uniqueness guards. | `concurrency.test.ts` | **RESOLVED** |
| **9** | **Rate Limiting & Abuse Prevention** | MEDIUM | Global and auth rate limiters in place. | Password brute forcing and API spamming. | Tiered IP-based rate limiting (30 requests/15m for auth, 500 requests/15m for API). | `hardening-security.test.ts` | **RESOLVED** |
| **10** | **Input Validation & Mass Assignment** | HIGH | Zod validation on request bodies, queries, and params. | Malformed input, extra malicious fields injected into database. | Strict Zod validation schemas stripping unrecognized fields. UUID and enum type verification. | `blood-request.test.ts`, `opportunity.test.ts` | **RESOLVED** |
| **11** | **SQL & ORM Injection** | CRITICAL | Prisma parameterized queries used throughout. | SQL injection via unescaped string concatenation. | No raw string concatenation in SQL; all queries use Prisma ORM or parameterized `$queryRaw`. | `auth.test.ts`, `admin.test.ts` | **RESOLVED** |
| **12** | **Cross-Site Scripting (XSS)** | MEDIUM | React 19 automatic JSX encoding; Helmet security headers. | Script injection via donor profile names or coordinator notes. | React default escaping, Helmet headers, explicit Content-Type JSON responses on API. | `hardening-security.test.ts` | **RESOLVED** |
| **13** | **CORS Restrictions** | MEDIUM | Explicit allowed origin whitelist (`CLIENT_URL`, `http://localhost:5173`). | Malicious origins making cross-origin credentialed requests. | Explicit origin reflection matching whitelist; wildcard `*` strictly prohibited with credentials. | `csrf-security.test.ts` | **RESOLVED** |
| **14** | **Sensitive Data in Logs** | HIGH | Default console logging could output passwords or tokens. | Secrets and medical details leaking into log aggregators. | Structured JSON logger with privacy sanitizer redacting `password`, `token`, `cookie`, and diagnosis fields. | `observability.test.ts` | **RESOLVED** |
| **15** | **Request Correlation (X-Request-ID)** | LOW | No correlation ID between client, API, and log entries. | Difficulty tracing distributed errors and debugging production issues. | Added `X-Request-ID` middleware assigning unique UUIDs to every request, response header, and log context. | `observability.test.ts` | **RESOLVED** |
| **16** | **Error Sanitization** | MEDIUM | Express default error handler could expose stack traces. | Leaking database errors, file paths, and environment internals in production. | Centralized error handler returning structured `{ error: { code, message, requestId } }`, hiding stack traces in production. | `hardening-security.test.ts` | **RESOLVED** |
| **17** | **Request Body Limits** | MEDIUM | Unbounded body parser could cause memory denial of service. | Large payload DoS attacks. | Explicit 1MB JSON and URL-encoded body limits configured in Express. | `hardening-security.test.ts` | **RESOLVED** |
| **18** | **Audit Logging Integrity** | HIGH | Key state changes logged in `AuditLog` table. | Lack of accountability for clinical actions and coordinator decisions. | Comprehensive audit events logged for logins, profile updates, opportunities, requests, and donations. | `audit-logs.test.ts` | **RESOLVED** |
| **19** | **Account State & Deactivation** | HIGH | Soft deletion supported on DonorProfile. | Deactivated donors continuing to receive opportunity alerts. | Deactivated and deleted accounts blocked at authentication and matching evaluation boundaries. | `authorization-security.test.ts` | **RESOLVED** |
| **20** | **Notification Consent Enforcement** | HIGH | Explicit donor preferences in `DonorProfile`. | Unwanted SMS/Email outreach violating privacy consent. | Outreach dispatcher validates `allowBloodRequestNotifications` before external dispatch. | `opportunity.test.ts` | **RESOLVED** |
| **21** | **Notification Idempotency & Retries** | MEDIUM | Phase 12 notifications created directly. | Duplicate alerts sent upon transient network errors. | Added bounded retry tracking (`attemptCount`, `lastAttemptAt`, `errorCode`) with duplicate prevention. | `notification.test.ts` | **RESOLVED** |
| **22** | **Graceful Process Shutdown** | MEDIUM | Direct process termination on restart. | In-flight HTTP requests cut off mid-transaction. | Handled `SIGTERM` and `SIGINT` signals with server connection draining and Prisma pool teardown. | `server.ts` | **RESOLVED** |
| **23** | **Health & Readiness Probes** | LOW | Single `/health` endpoint. | Orchestrator routing traffic before database is ready. | Separated `/health/live` (process liveness) and `/health/ready` (database reachability). | `health.test.ts` | **RESOLVED** |
| **24** | **Admin Audit Explorer** | MEDIUM | Audit logs existed only in database tables. | Coordinators unable to review audit history easily. | Implemented `GET /api/v1/admin/audit-logs` and React admin UI with live filtering and detail modal. | `audit-logs.test.ts` | **RESOLVED** |
| **25** | **Clinical Terminology Invariant** | MEDIUM | Match scores previously risked being mistaken for medical clearance. | False confidence in donor eligibility prior to physical lab crossmatch. | Renamed and documented all scores as "Basic screening match score". Disclaimers added across all opportunity pages. | Frontend verification | **RESOLVED** |
| **26** | **Environment Secrets Validation** | HIGH | Scattered environment variable reads. | Startup with missing `JWT_SECRET` or insecure defaults in production. | Centralized Zod schema validating required environment variables on server boot. | `env.ts` | **RESOLVED** |
